# Automatic finance acceptance containment

Current enforced behavior: persisted active posting rules cannot authorize new posting. New automatic execution denies `FINANCE_POSTING_RULE_APPROVAL_REQUIRED` after authoritative cash custody/outbox/source verification and before period/rule evaluation, number allocation, journal/document/audit/outbox mutations. Generic payment/refund/carrier/payable ingestion denies `FINANCE_SOURCE_AUTHORITY_REQUIRED` before transaction; generic stored sources cannot bypass via posted status. Existing invoice-specific containment retains its code.

Cash queue messages still identify durable accepted outboxes only. Authoritative custody/order/company/tenant/legal-entity, exact money and source integrity checks remain intact; matching ingestion does not reset the record and PostgreSQL duplicate ingestion remains serialized. Custody source acceptance is not accounting-rule acceptance. Existing validated cash posting receipts may be returned after current durable ownership/source/result graph checks without another posting; this neither certifies historical rule approval nor authorizes replay. No posted record is rewritten.

Service/repository manual retry now requires fresh selected context, `finance.exceptions.manage` and explicit company scope, verifies actor/company and then denies before reads/requeue/audit. Missing context fails403. The existing retry body stays behind containment. Worker claim/lease behavior is unchanged; guarded non-posted attempts use the existing bounded exception fields and are not automatically requeued. Posted records are excluded from exception updates. These operational exception annotations are permitted diagnostics, not new financial business effects or exact-once delivery evidence.

Backend compatibility: new postings are unavailable until accepted immutable configuration exists; generic unsupported source ingress rejects instead of creating an unaccepted source row. `/source-events/:id/retry` responds409 for an otherwise authorized request. Rule configuration writes remain contained. Cash custody collection/handoff/settlement and cash source ingestion remain supported; this does not restore invoice issuance, payments/refunds accounting, carrier/payable posting or client flows. Clients are deferred; no frontend/driver edits or browser/device claim.

Missing business decisions: independent company-scoped checker eligibility; immutable accepted rule/version/proposal identity; activation/supersession/cancellation/revocation treatment of previously accepted work; approved account mappings, pricing/FX provenance and conversion policy. Generic sources additionally require authoritative source-specific extraction/provider/document acceptance rather than trusting committed JSON or queue fields. No synthetic approval, first membership, human impersonation, override or default mapping is introduced.

Tests now assert current denial, exact durable source provenance, no ledger/audit/number/business-outbox effects and unchanged historical receipts. Prior synthetic successful posting/late-outbox rollback schedules remain historical evidence of mechanisms behind containment, not current enabled workflow validation. No new successful posting, transactional rollback execution, external delivery or real transport claim is made. No schema change; previous offline validation reused.
