# Trial-balance read containment

Current enforcement: HTTP, service and repository now pass the selected authenticated actor, not companyId as authority. Fresh current membership context, `finance.reports.read` and explicit stored company scope are required. Active legal entity, tenant and company ownership are repeated at the report queries. Missing/null/inactive/foreign ownership yields no report; another selected company in the same tenant remains separate. No default legal entity, configuration, period or financial mutation is created by reads.

Only posted/reversed journals in the requested date range contribute, preserving previous financial calculation semantics and exact Decimal aggregation. A read transaction uses RepeatableRead for graph checks and aggregation. Inconsistent document/entity, line/entity/account/parent, reversal/entity or document/journal lifecycle rejects the whole report with `FINANCE_REPORT_INTEGRITY_REJECTED`, rather than silently omit corrupt data and present partial totals. Legacy null line bridges are explicitly rejected. This does not certify historical financial authority or create approved manual posting.

PostgreSQL sums can exceed the column's numeric(20,4) precision. Report addition/subtraction uses exact four-place scaled integers and converts back to Decimal for the response, avoiding default significant-digit rounding. This follows the existing stored base-money scale; it introduces no FX/conversion/accounting rule. Unit and actual PostgreSQL cases preserve `20000000000000000.0998` exactly, including negative account differences.

Accounts use a minimal explicit id/code/name/type projection; amount strings retain the previous JSON contract. Output is bounded to 10,000 grouped accounts, rejecting overflow rather than truncating. This bound does not prove bounded database scan time; production query deadlines, large-range performance and a controlled concurrent posting-versus-report schedule remain separate verification work.

The only source caller is the finance HTTP trial-balance route; the port and service signature change from companyId to AppUser. Dates must be finite and ordered. Unknown HTTP query fields (including ownership filters) now reject instead of being stripped. No frontend/driver implementation or browser compatibility is claimed; later client work must preserve fresh selected context. Normal authorized response fields and exact monetary representation remain intact.

No migration is introduced here; prior schema validation is reused. Focused mocked/HTTP and isolated PostgreSQL evidence is recorded in the backlog. Real PostgreSQL executes the group-by predicates and transaction; mocks do not prove database isolation, and no provider/Redis/external effects were tested.

Existing manual post/reverse, new invoice issuance/execution, sensitive configuration and unapproved cash accounting mappings stay contained. NOT VALID historical certification, general financial dimensions/source authority, complete SQL immutability, permission/revocation timing, RLS and all earlier release gates remain unresolved. Fresh checks and a report snapshot do not prove immediate revocation across concurrent changes.
