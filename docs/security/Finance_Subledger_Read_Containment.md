# Finance subledger read containment

Current enforced behavior: receivables aging, payables aging and unapplied cash require a mandatory selected AppUser at HTTP/service/repository boundaries, fresh finance.receivables.read or finance.payables.read and an explicit stored selected-company grant. Missing context, revoked selection and unbound/inactive tenant/company/entity fail closed. No company-only repository overload remains. Internal ownership fields and unknown HTTP filters reject rather than selecting a workspace. All pages, complete filtered summaries and cursors repeat active tenant/company/entity predicates.

Ownership graph: receivables require a matching tenant/company invoice, order and customer (including null equality) and stored source event with that invoice identity/type. Payables require the owned carrier bill and configured provider company/domain/code, currency and bill source identity/type. Cash requires the owned order/customer and stored source resolving a matching configured payment intent or refund in that company/order/currency. These reads reflect stored historical amounts; they do not certify approved pricing, FX, independent accounting source acceptance, approval or provider settlement. Unowned or inconsistent parent records are hidden; totals are for the visible owned subset, not a certification of all historical liabilities. No backfill, financial writes or execution restoration.

An explicit customer filter additionally uses requireCustomerEntityReference, including existing customers.read and customer scope; finance permission alone does not grant master-record access. Carrier filters resolve only owned carrier configuration. Company-wide finance reads require the existing explicit company grant; warehouse-only/customer-only selections cannot substitute. No policy.override bypass added. IDs returned in obligation projections belong to verified source relationships, and no master personal detail is queried.

Allocation checks preserve existing as-of calculation, refund sign, aging buckets and exact fixed-four-decimal output. Currency, source/entity and payment/refund references must agree; payables additionally require the same entity/payable/run line/bank, exact line amount, executed run and executed/allocated line, and accounting source. An inconsistent relevant allocation rejects the report409 FINANCE_SUBLEDGER_REFERENCE_CONFLICT instead of reporting a partial balance. Current source presence is ownership/correlation evidence, not independently accepted accounting authority. Underlying projection/write integrity remains a separate task.

Read queries use a bounded RepeatableRead transaction explicitly set READ ONLY (2s admission,10s transaction). Cursor predicates include all filters and balance eligibility; summaries cover the full filtered subset, not only the returned page. Cash has explicit safe SQL columns and one bulk application query,1000-child total page limit, with overflow denial instead of truncation. Raw metadata, worker/source internals, idempotency and unrelated receivable IDs are omitted from cash children. No storage/provider/outbox effects occur. Concurrent revocation after the fresh membership check remains a timing boundary; no immediate distributed-revocation claim. Infrastructure query timeouts/performance under real data require later verification.

Compatibility: mandatory actor/internal query contract; HTTP paths and items/summary/nextCursor envelopes retained. Unknown filters now400, unavailable owned entity404, inaccessible master filters403/404, inconsistent allocation409 and detail overflow409. The HTTP error code retains the existing generic FINANCE_REFERENCE_ERROR format; named domain codes above are internal/service results. Existing supported currency-filter choices remain unchanged, including rejection of EUR filters even though historical EUR rows can be read without a filter. Legacy unowned/unprovable source graphs disappear from these covered reports. Cash internal metadata/source/application linkage fields omitted. Clients remain deferred and no browser/device compatibility verified. Rollback must retain authorization/graph/projection checks or disable these reads.

Focused mocked/HTTP and disposable PostgreSQL evidence is recorded in Security_Hardening_Backlog.md. No schema migration in this read slice. Previous NOT VALID/null certification, immutable acceptance, checker eligibility, approved mappings/FX, recovery, Redis revocation/lifecycle, S3/device/provider and RLS blockers remain open.
