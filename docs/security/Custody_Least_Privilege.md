## Implemented correction and contracts

Custody-only authorization now reloads the selected context with requireFresh/explicitScopesOnly, the owned Order and latest append-only custody action. Exact owning company is mandatory; conflicting assigned company rejects. Before the bounded Order row lock, callers must prove the specific current custody relationship or an owned matching receipt; after waiting, context/source/receipt are reloaded and authorized again. Expected event/timestamp, immutable normalized intent hash, database uniqueness, whole-parcel manifest, action transitions and transactional effects are unchanged. Generic dispatch/list/detail/assignment/leg/file policies are not broadened.

| Actor / operation | Specific authority |
|---|---|
| Receiving staff / intake | Latest pickup offer's exact destination warehouse, active selected company context, intake permission and explicit warehouse scope |
| Origin staff / dispatch, last-mile offer | Latest warehouse custody and matching currentWarehouseId, specific action permission and explicit warehouse scope |
| Linehaul driver / accept | Latest transport nomination's exact user/company membership, active local tenant/company bridge, linehaul eligibility, telemetry and transport-accept permission |
| Destination staff / receive | Latest accepted transport's exact destination warehouse, receive permission and explicit warehouse scope; leg arrival alone remains insufficient |
| Local driver / pickup offer, last-mile accept, deliver | Initial current pickup assignment/source or latest nominated/accepted exact company membership; appropriate local-driver eligibility, telemetry and specific action permission |
| Confirmed retry | Original actor/user/TM/CM/tenant/company/order/intent identity; current action permission and original acting warehouse scope or driver eligibility. Exposes only original receipt result, even after custody moves; does not grant current order visibility |

GET `/api/orders/:id/custody` preserves orderId/updatedAt/custody fields and adds `parcelIds` (at most 100) and `pickupTrackingId` (only current authorized pickup actor/source). Reads require shipment.view and either the current specific custody relationship/action capability or existing explicit membership order scope. Accepted drivers can inspect their current transport/last-mile/delivered custody, without assignCourier/company grants. Incoming staff no longer require general company/order visibility beyond their exact custody relationship. Reads never return receipt intent, audit history, money or protected files. An old recipient with only an original receipt cannot read the current order after custody moves.

Proof capability and multipart upload preflight use the existing assigned-proof policy or the specific current pickup/accepted last-mile membership with shipment.update, telemetry and relevant custody capability. Upload checks run before multipart file buffering; proof service rechecks before storage and confirmation as before. No proof-read/signed-URL/global order-query fallback was added. Existing PNG processing, normalized proof identities, immutable storage and incomplete-reconciliation behavior remain. No new API request fields or success-shape changes for POST custody/proof; snapshots only gain the two additive fields. Known order/driver/warehouse IDs must come from an authorized operational workflow; this correction adds no general incoming-work discovery or driver-selector API. Earlier pickup status operations, unrelated driver order lists/detail and warehouse/driver provisioning are unchanged/deferred.
