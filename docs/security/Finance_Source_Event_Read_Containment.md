# Finance source-event and exception reads

Current enforced behavior: existing GET `/source-events` and `/exceptions`, service and repository lists require fresh selected tenant/company membership, `finance.exceptions.read` and an explicit stored company scope. No optional company-only entry point remains. Active tenant/company/legal-entity ownership is repeated at queries; missing/null/inactive ownership returns no rows. Status and bounded page inputs are allowlisted; cursors must match the same ownership and status predicates before keyset pagination.

Linked rules, documents and journals must belong to the selected legal entity. Rule lines require populated same-entity account bridges. Foreign/conflicting ownership is hidden; same-entity journal/document pairing conflicts and incomplete posted results reject the whole page, including its pagination sentinel. Reads never create legal entities, retry events or mutate configuration. Current eligibility is checked before reads; concurrent revocation after that check remains a timing boundary, not immediate distributed revocation.

Explicit response projections retain source/correlation identifiers, selected company/entity identifiers, status, attempts, authoritative dates and minimal rule/document/journal summaries. Raw payload, payload hash, worker claim details, scheduling internals and raw errors are omitted. The `{items,pageInfo}` envelope and event names remain unchanged. Unknown ownership/filter fields now reject400 instead of being silently stripped. Repository/service callers must supply verified actor context. Clients are deferred; consumers relying on omitted fields need later adaptation. No new detail endpoint or worker authorization bypass was added.

This is read containment, not source-specific financial acceptance. Simple source-event reference FKs still permit cross-company/entity combinations in storage; disposable synthetic probes demonstrate those gaps and that reads hide them. No historical rows are mapped, no source execution is restored and no immutable rule acceptance, approved accounting mapping, checker eligibility or FX policy is inferred. Independent durable acceptance remains required for new financial execution; retry stays contained. Future additive source-reference constraints must protect new/changed references without claiming historical certification.

Validation/evidence and owned disposable cleanup are recorded in Security_Hardening_Backlog.md. Mocked HTTP tests are separate from real PostgreSQL predicates; no real provider, Redis, storage or client verification. Nullable/NOT VALID certification, broader financial dimensions, SQL immutability, distributed revocation, recovery and RLS remain release gates. Migration76 precedes this application slice; rollback must preserve authorization and output containment or disable the endpoints.
