# Bounded authentication rejection diagnostics

Confirmed gap after chart checkpoint 93310326c53440f3a968c8a54143d4ca053e539b: login and refresh handlers sanitize responses but do not emit security rejection diagnostics. The shared limiter safely returns 429/503 without credential disclosure, also without security telemetry. Accepted CredentialSecurityEvent records require authoritative identity/tenant bridges; failed or unknown authentication cannot safely populate them.

Plan: add a fixed-code, fixed-cardinality monotonic-window diagnostic budget shared in this process. Report only a static event/code and bounded suppressed count through a static JSON console diagnostic, independent of request logger bindings. Source review found src/index.ts sets Fastify logger:false, so a root Fastify logger would discard these diagnostics; the first passing test run exposed that evidence limitation during review and the sink was corrected. Cover login credential/selection rejection, refresh rejection and unexpected failure with no exception details; wrap existing authentication admission hooks without changing limits or storage. Expected credential-verified selection-required 409 is a normal flow and is not a rejection. Diagnostic sink failure must not change authorization or response. No persistence, tenant inference, new infrastructure, schema, tokens, IP/email/body/header/resource IDs or client changes. Accepted audit remains independent and transactional.

Acceptance: unknown codes cannot create cardinality or output; flood limits and renewal/suppressed counts are bounded; sensitive input and exception strings never reach the sink; limiter denial runs before credential/session work; status/error/selection contracts and no-session rejection remain unchanged. Run helper and HTTP-injection cases plus affected session consumers and no-emit. PostgreSQL/Redis need no new run because their exercised implementation/schema is unchanged. Diagnostics are sampled process-local telemetry, not a complete durable audit, fleet-wide rate cap or a retention policy.
