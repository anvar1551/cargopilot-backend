## Current enforcement and blocked requirement

GET /api/finance/legal-entity and direct getLegalEntity entry points require full server-reloaded context, finance.settings.read and an explicit scope for the selected company. Repository predicates require the entity tenant/company, active entity, active tenant and company ownership/activity to agree. The projection exactly preserves the inspected frontend FinanceLegalEntity fields and omits audit actor IDs and unrelated relations. Missing context/scopes/revoked membership deny; a hidden/absent entity returns null, as before for absent configuration.

Architecture section 12 explicitly requires separate actors for sensitive financial configuration. Current PUT/configureLegalEntity has no proposal, checker or durable acceptance. Holding finance.settings.manage cannot replace approval. HTTP/service writes require fresh context and permission, then reject with 409 FINANCE_CONFIGURATION_APPROVAL_REQUIRED before business reads/writes. Direct repository configuration also unconditionally rejects; caller approval/checker fields cannot supply a bypass. HTTP configuration schema is strict and rejects ownership/actor/approval fields (400). The legacy normalization, posted-journal base-currency and existing-period fiscal-calendar restrictions and audit/outbox transaction remain behind this unconditional containment guard for future review; they are not a currently executable configuration flow.

New legal-entity tenant derivation is therefore NOT implemented as an accepted write. Restoration requires an ownership-bound durable proposal/approval operation with independent authorized checker, server-derived tenant/company, atomic configuration/audit/outbox and locking against posting/period creation. Approved checker eligibility and sensitive-change acceptance need explicit definition; no new role, accounting, FX, override or self-approval policy is fabricated. Null-owned historical rows cannot be silently assigned ownership. No configuration-versus-posting concurrency claim. Revocation after the fresh read remains a timing boundary.
