# Generic integration webhook admission and native deadlines

## Confirmed gap and implementation
Stripe-specific callback limits did not cover generic integration HMAC ingress. The gateway/resolver/writer previously used the general Prisma client without callback admission. Now a process-wide eight-permit gate surrounds resolver, signature verification and atomic persistence. Exhaustion returns503 WEBHOOK_INGRESS_CAPACITY before any provider/secret lookup, crypto or writes; no waiting application queue, immediate retry or automatic replay. A permit remains held until its underlying promise settles, including caller timeout/disconnect. Failure releases only settled work.

Raw UTF8 body is explicitly bounded to1MiB at HTTP parsing and direct gateway entry. Parser limit precedes string parsing/verification; direct over-limit input fails413 before lookup. Existing raw-body HMAC verification, header minimization, source ownership and atomic receipt semantics remain intact.

Resolver/receipt writer now use a separate lazy PostgreSQL pool: max8, acquisition/connect1s, statement3s, lock1s, idle transaction5s. Atomic acceptance retains acquisition2s/transaction5s and local statement3s/lock1s. Import/construction loads no dotenv and opens no connection. Runtime uses configured direct DATABASE_URL; missing URL or Accelerate configuration is contained503 WEBHOOK_INGRESS_DATABASE_UNAVAILABLE rather than claiming native deadlines for an unsupported transport. Fastify onClose closes only this pool/client. Global application and payment callback pools remain unchanged.

No request response timer frees permits, abandons a database transaction, issues provider requests or claims persistence succeeded. Capacity/unavailable responses are sanitized503 and not acknowledged; database errors likewise remain unacknowledged, with existing sanitized500 boundary when not explicitly classified. Native deadlines are database/server/acquisition controls, not proof of cancellation during arbitrary network partition. Up to eight unresolved tasks/connections can retain capacity and cause fail-closed admission until transport settles. Shutdown completion, packet blackholes, replica/distributed fairness and total process-wide capacity across replicas remain unverified infrastructure gates. This is bounded admission, not a deployed rate/fairness/probe configuration.
