## Implemented milestone A — bounded tariff publication

Current enforced behavior: fresh active selected user/company/tenant membership, explicit company scope and pricing.tariffs.propose or pricing.tariffs.approve. Authority is reloaded after the bounded company authoring lock; this closes permission revocation during that lock wait, not every last-read/concurrent revocation race. Independent means a different user, even when both users hold both permissions. Customer-specific snapshots also require current customers.read and applicable customer/object scope. Route references must belong to the selected company; snapshots freeze explicit route/leg fields, excluding arbitrary metadata.

Only FIXED_LANE bucket configuration with null transitPricingConfig is supported in this milestone. Stored weight/rate decimals and currency are copied exactly as strings, without a calculation, rounding or currency conversion. Linear and LEG_TRANSIT proposal/publication remain unavailable with TARIFF_CALCULATION_POLICY_REQUIRED because current quote semantics do not establish compatible exact authority. Operational multi-leg logistics, existing estimates and their precedence are unchanged. No accepted order-price, exception/revision or new invoice writer has been added.

Additive routes under /api/pricing:

- POST /tariff-plans/:id/versions: operationId UUID, expectedGeneration from the owned tariff's contentGeneration, bounded reason. Returns original version ID/generation/hash/server time on an authorized matching retry.
- GET /tariff-plans/:id/versions/:versionId: pricing.read, explicit company and any customer scope; returns the explicit frozen configuration and minimal decision projection.
- POST /tariff-plans/:id/versions/:versionId/decision: operationId UUID, exact displayed contentSha256, approved or rejected, bounded reason. Requires independent approval capability. Returns original owned decision on a matching retry, even after later supersession; never repoints history.

Unknown ownership/money fields reject. UUIDs and reasons normalize before request hashing. Receipts are unique by tenant/operation, bound to the exact initiating selected memberships/user/intent; another user or selected company cannot reuse them. One proposal per plan generation and one terminal decision per version; a rejected generation needs an actual new draft generation, not receipt reset. Versions and decisions ARE the immutable publication/approval/rejection/supersession audit facts; accepted financial audit/outbox facts are not fabricated. Untrusted failed requests do not create accepted facts.

Schema expansion: migration 20261004110000_tariff_publication_authority adds owned immutable version/decision tables, compound actor/user/tenant/company bridges, exact version/generation/hash and maker references, independent-user CHECK, approved-pointer completeness and compound FK. Row and TRUNCATE guards protect history. Parent generation is server/database maintained; rate changes, including change-and-restore, advance it. Current authoring and publication share a bounded company transaction lock; pending approval also compares the actual frozen template content. Publication decision and pointer/status change commit together. Pointer cannot clear or rewind. Immutable versions survive later draft changes; the old pointer is an approved historical version, not proof the current mutable draft has been approved.

Bounds: 500 rates, 100 template legs, 192 KiB serialized snapshot, 1,000-character reason; transaction maxWait 2 seconds/timeout 10 seconds, SQL lock 2 seconds/statement 5 seconds. No provider, storage, job or financial outbox effect. Referenced plan deletion is rejected transactionally and cannot delete its rates; archive retains history. No legacy/null ownership backfill. No new permissions are delegated to existing roles: catalog definitions alone grant nothing; production provisioning remains deliberately reviewed and out of this batch.

Rolling deployment requires the additive migration and compatible generated client before the new writer; stop old tariff authors that do not take the authoring lock. Database generation checks still reject stale approvals, but old writers are not claimed to share the tested application serialization. Preserve immutable evidence and restrict new entrypoints on rollback rather than restoring unapproved financial execution. Clients remain deferred; no selection/approval UI or production grants were installed.
