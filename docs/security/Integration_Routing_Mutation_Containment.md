# Carrier routing mutation containment

## Confirmed gap and enforced boundary
Public routing create/update/delete previously used user-global memberships or policy.override and id-only updates/deletes. Configuration actions had no durable accepted version/action journal, while provider/fallback/template/leg references had only separate existence relationships. The current catalog can hold inconsistent graphs (demonstrated by the preceding disposable PostgreSQL read tests). Do not turn a mutable caller configuration into accepted carrier execution authority.

All three public mutations now require fresh exact tenant-bound selected company membership, integration.routing.manage and explicit company scope. Create company is an equality assertion. Update/delete perform selected active owner id-only lookup; foreign/null-owned context cannot expose configuration. After authorization,409 INTEGRATION_ROUTING_CONFIGURATION_WORKFLOW_REQUIRED prevents any configuration, order, outbox, provider, secret, job or external business effect. There is no override, user-global catalog, default company or alternate mutation fallback. Removed obsolete normalizers/private mutation helpers and actual create/update/delete code, retaining input types/route contracts and automatic selection unchanged.

This is containment, NOT restored configuration functionality. Public users cannot create/update/delete carrier routing until durable configuration/version/action and ownership graph integrity are implemented. History-preserving retirement and accepted operation revocation/cancellation policy must be explicit; do not reset accepted jobs or invent reacceptance/provider guarantees. Non-financial version/action persistence is technically ready; finance checker/accounting/FX acceptance remains a separate policy blocker.

HTTP returns sanitized403/404/409/500 with controlled error code. No internal errors or protected configuration returned. Existing routing inventory remains available under its scoped snapshot contract. No client implementation, schema/migration or deployment change.
