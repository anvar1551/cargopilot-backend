# Selected integration event metadata

Current enforced application behavior: webhook/canonical lists reload the exact selected tenant/company membership with `integration.outbox.read` and explicit company scope. Queries repeat active company/tenant ownership and server-owned provider ID/company/domain/code/environment tuples. An empty configuration set is false; over 100 matching configurations returns `409 INTEGRATION_READ_CAPACITY` rather than partial totals. Counts and lists share the predicate. Pages are bounded to 1–10000, limits 1–100, search to 180 characters and provider-code metadata only. Permission revocation after the fresh check remains a concurrent timing boundary.

Canonical metadata must reference exactly one matching source: `inbound_webhook` references an authenticated webhook with matching company/provider/domain/code/environment and no outbox ID; `outbound_response` references an owned matching outbox with no webhook ID. Populated outbox/order ownership also agrees with the selected tenant/company. Missing/conflicting/dual source links are inaccessible. Company-owned metadata without an order bridge does not authorize business payload reads or execution. A webhook security record with failed verification may appear in the owned webhook metadata list, but cannot supply the authenticated source required by the canonical metadata list.

New additive migration `20261002230000_canonical_outbox_source` and matching optional Prisma relation enable authoritative outbox source traversal. The existing unique outbox ID remains the one-to-one target. The `NOT VALID` foreign key protects new/changed non-null source references, prevents referenced outbox deletion/ID changes, and preserves existing rows without certifying them. Null source IDs remain possible, and this simple existence constraint alone does not prove tenant/provider/source-type consistency; application read predicates provide those checks. Historical certification and stronger write-side source consistency remain separate unfinished work. No committed migration was edited; no historical data was rewritten. Recovery must preserve enforcement or disable affected paths, never restore global access.

Inspected writers: the carrier publisher derives outbound source IDs from durable claimed outbox records; the webhook gateway derives inbound IDs/provider context from verified ingress persistence. Their canonical repository, deduplication, claim/retry behavior and durable worker authorization are unchanged. No provider contract, transition, accounting rule or uncertain replay was invented. The foreign key may reject malformed source IDs previously accepted; callers must preserve the actual durable source. Manual replay remains contained.

Compatibility: `{items,total,page,limit}` envelopes remain, but protected/raw/free-text detail keys are `null`: provider event IDs, aggregate/event identifiers, nested canonical business data, raw errors, IP/user-agent details. Queries do not retrieve payload/body/header/error fields. The bounded SHA256 digest, verification flag, processing metadata and selected provider metadata remain. Search no longer probes provider event IDs. Client changes are deferred; detailed business-event access would require source-resource permission/scope checks, not this integration metadata permission.

Evidence is recorded in the backlog: focused mocked/query/HTTP tests, a related integration milestone, offline Prisma validation, ignored-node_modules-only generation, no-emit checking and actual disposable PostgreSQL source/integrity/projection tests. Native database tests use the actual public service exports and server membership queries; only the application Prisma module is redirected to the exclusively owned synthetic database. They prove covered query predicates and the new constraint, not real provider authentication/transport, immediate revocation, historical certification or complete isolation. Existing callback signature/deadline/deduplication evidence remains distinct. No application build or dist rewrite is needed.

Remaining: immutable non-financial configuration action/version auditing, secret pointer/version concurrency, routing authority, canonical writer graph constraints and other finite backend items. Financial independent acceptance/checker/accounting/FX policy, recovery/cancellation, nullable/historical certification, Redis/S3/native transport and RLS release gates remain open; containment is not restored functionality.
