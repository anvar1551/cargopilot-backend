# Production Environment Reference

This file is the deployment checklist for CargoPilot backend. Keep provider credentials in the admin UI where supported; do not add provider secrets to source control.

## Required API variables

| Variable | Purpose | Notes |
| --- | --- | --- |
| `NODE_ENV` | Runtime mode | Use `production`. |
| `PORT` | API port | Render uses `4000` in `render.yaml`. |
| `DATABASE_URL` | Prisma/Postgres connection | Required for API and all workers. |
| `JWT_SECRET` | Access-token signing | Must be stable. Rotating signs out users. |
| `REFRESH_TOKEN_SECRET` | Refresh-token signing | Must be stable. Rotating invalidates refresh sessions. |
| `CLIENT_URL` | Main frontend origin | Example: `https://app.example.com`. |
| `CORS_ORIGINS` | Extra allowed origins | Comma-separated. Include staging/ngrok only when needed. |
| `PAYMENT_CONFIG_MASTER_KEY` | Payment secret encryption | Must be stable. Changing it breaks stored payment provider secrets. |
| `INTEGRATION_CONFIG_MASTER_KEY` | Integration secret encryption | Must be stable. Changing it breaks stored carrier/SMS/webhook provider secrets. |

## Required infrastructure variables

| Variable | Purpose | Notes |
| --- | --- | --- |
| `REDIS_ENABLED` | Enables Redis-backed realtime/read models | Use `true` in production. |
| `REDIS_URL` | Redis connection string | Required for realtime, analytics, workers, and locks. |
| `REDIS_PREFIX` | Key namespace | Use one prefix per environment, for example `cargopilot-prod`. |
| `AWS_REGION` | S3 region | Required for labels/proofs if S3 is enabled. |
| `AWS_S3_BUCKET` | S3 bucket | Required for uploaded labels/proofs/invoices. |
| `AWS_ACCESS_KEY_ID` | S3 access key | Use least-privilege bucket access. |
| `AWS_SECRET_ACCESS_KEY` | S3 secret key | Store only in deployment platform secrets. |

## Feature switches

| Variable | Production value | Purpose |
| --- | --- | --- |
| `PAYMENTS_ENABLED` | `true` only after provider setup | Allows online payment intent creation. |
| `INTEGRATION_OUTBOX_IN_API` | `false` | Outbox should run in its own worker. |
| `ANALYTICS_WORKER_IN_PROCESS` | `false` | Analytics should run in its own worker. |
| `ORDER_LABEL_MODE` | `queue` | Labels should be generated by worker. |
| `ORDER_LABEL_SECOND_CODE_MODE` | `barcode` | Label second-code rendering mode. |

## Provider credentials

Use admin UI for provider credentials:

- Payments: `Billing & Pricing -> Payment Providers`
- Carriers/SMS/Webhook sinks: `Integrations -> Providers`

For local smoke tests only, scripts may read `SMOKE_*`, `FAKE_CARRIER_*`, and `INTEGRATION_ADMIN_*` variables. Do not deploy those as production requirements.

## Optional tuning variables

Most timeout/cache variables already have safe defaults. Only tune them after a measured issue:

- Redis: `REDIS_COMMAND_TIMEOUT_MS`, `REDIS_OP_TIMEOUT_MS`, `REDIS_UNAVAILABLE_COOLDOWN_MS`
- Analytics: `ANALYTICS_*`, `OPS_*`
- Live map: `LIVE_MAP_*`
- Labels: `ORDER_LABEL_*`
- Support: `SUPPORT_*`

## Rotation policy

- Rotate `JWT_SECRET` only when forced; it signs out active access tokens.
- Rotate `REFRESH_TOKEN_SECRET` only when forced; it invalidates refresh tokens.
- Rotate `PAYMENT_CONFIG_MASTER_KEY` and `INTEGRATION_CONFIG_MASTER_KEY` only with a planned data re-encryption migration.
- Rotate provider API keys/secrets inside the admin UI. This creates a new encrypted provider secret version without changing system master keys.
