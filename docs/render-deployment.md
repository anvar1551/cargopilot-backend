# Render Deployment

## Recommended layout

Deploy the backend as these Render resources:

- `cargopilot-api` as a Docker web service
- `cargopilot-analytics-outbox-worker` as a Docker background worker
- `cargopilot-integration-outbox-worker` as a Docker background worker
- `cargopilot-label-worker` as a Docker background worker
- Postgres and Redis as managed services or external URLs

The repo now includes `render.yaml`, so the easiest path is a Render Blueprint deploy.

## First deploy

1. Push the backend repo to GitHub.
2. In Render, click `New` -> `Blueprint`.
3. Select the backend repository.
4. Render will detect `render.yaml` and propose:
   - one web service
   - three workers
5. Fill the prompted secrets:
   - `DATABASE_URL`
   - `REDIS_URL`
   - `CLIENT_URL`
   - `CORS_ORIGINS`
   - `AWS_S3_BUCKET`
   - `AWS_ACCESS_KEY_ID`
   - `AWS_SECRET_ACCESS_KEY`
6. Click `Apply`.

## Required values

The blueprint wires these automatically:

- `JWT_SECRET` generated by Render
- `REFRESH_TOKEN_SECRET` generated by Render
- `PAYMENT_CONFIG_MASTER_KEY` generated by Render
- `INTEGRATION_CONFIG_MASTER_KEY` generated by Render
- `NODE_ENV=production`
- `PORT=4000`
- `PAYMENTS_ENABLED=false`
- `REDIS_ENABLED=true`
- worker processes reuse the API `DATABASE_URL`, `REDIS_URL`, `REDIS_PREFIX`, and required secret keys

You must provide these at creation time:

- `DATABASE_URL`
- `CLIENT_URL`
  - example: `https://app.your-domain.com`
- `CORS_ORIGINS`
  - example: `https://app.your-domain.com`
- `REDIS_URL`
- `AWS_S3_BUCKET`
- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`

Keep `PAYMENT_CONFIG_MASTER_KEY` and `INTEGRATION_CONFIG_MASTER_KEY` stable after first deploy. Changing either without re-encrypting database secrets breaks stored provider credentials.

## Optional payment values

Payments are disabled by default in the blueprint.

If you enable payments later:

- set `PAYMENTS_ENABLED=true` in `cargopilot-api`
- configure provider credentials from admin UI (`Billing & Pricing` -> `Payment Providers`)
- for Stripe, use:
  - `Secret` = `sk_...`
  - `Webhook Secret (serviceId)` = `whsec_...`
  - callback endpoint: `/api/payments/stripe/callback`

## After deploy

Run these checks:

1. Open `https://your-api-domain/api/health`
2. Log into the frontend against the new API
3. Create one order
4. Open order details
5. Confirm label generation works
6. Check `cargopilot-label-worker` logs for label processing errors
7. Check `cargopilot-analytics-outbox-worker` logs for analytics projection errors
8. Check `cargopilot-integration-outbox-worker` logs for carrier/SMS/webhook dispatch errors
9. Open `Integrations -> Event Inbox` and verify canonical events are visible after a webhook or fake-carrier test

## Auto deploys

`render.yaml` currently uses:

- `autoDeployTrigger: commit`

That means every push to the connected branch will redeploy automatically.

If you later add GitHub Actions and want stricter CI/CD, change all services to:

```yaml
autoDeployTrigger: checksPass
```

Then let GitHub Actions run the checks before Render deploys.
